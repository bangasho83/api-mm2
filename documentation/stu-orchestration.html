STU-Orchestration

Architectural uncertainty in orchestrating iterative multi-agent LLM workflows with non-linear handoffs, context propagation across cycles, partial failure, and bounded termination.

Ingestion Storage Orchestration Generation

Scientific and Technological Uncertainty (STU)

It was not known whether iterative multi-agent LLM workflows — where output from one cycle conditions the next, failures are partial, and context must propagate across non-linear handoffs — could be orchestrated reliably using existing execution models (single-call, linear chain, or stateless workers), or whether a purpose-built orchestration model was required.

H1 — Single LLM Call with Rich Context

Single gpt-4o-mini call with the full campaign context injected as a monolithic prompt. Token attention degrades for context beyond ~1,500 tokens; sections at the tail of the prompt receive reduced model attention. No re-execution path on partial failure — a 45-second timeout discards all partial output.

// services/campaign-brief-service.js : 102–116
// PSEUDOCODE: H1 — single call, no iteration boundary
const response = await Promise.race([
  openai.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: systemPrompt },
      { role: 'user',   content: userPrompt   }  // full context in one shot
    ],
    temperature: 0.7,
    max_tokens: 1500  // entire brief must fit in single completion
  }),
  new Promise((_, reject) =>
    setTimeout(() => reject(new Error('OpenAI API timeout (campaign brief)')), 45000)
  )
]);
// FAILURE 1: no iteration — model cannot refine output across cycles.
// FAILURE 2: 45 s timeout discards all partial progress with no checkpoint.
// FAILURE 3: context not partitioned — model attends poorly to distal sections.

H2 — Linear Chained Calls (Brief → Image Prompt)

Two sequential LLM calls: call 1 generates the campaign brief, call 2 derives an image prompt from the brief. Context passed between calls as a raw string. A malformed section in call 1 propagates into call 2 with no correction path; brittle regex parsing causes context drift across the chain boundary.

// PSEUDOCODE: H2 — brittle regex section parser (context-as-raw-string)
function parseBriefSections(content) {
  const sections = { campaignTitle: '', objective: '', keyMessage: '', ... };
  const patterns = {
    campaignTitle: /\*\*Campaign Title\*\*[:\s—-]*(.+?)(?=\n\*\*|$)/is,
    objective:     /\*\*Objective\*\*[:\s—-]*(.+?)(?=\n\*\*|$)/is,
    // ... per-section regex — fails if model deviates from expected format
  };
  for (const [key, pattern] of Object.entries(patterns)) {
    const match = content.match(pattern);
    if (match && match[1]) sections[key] = match[1].trim();
  }
  return sections;
  // Context passed as raw string between pipeline stages = context drift risk.
}

H3 — Local Worker Architecture (Independent Workers Per Stage)

Independent worker process per pipeline stage (brief generation, image prompt derivation, image generation). Workers could not share partial LLM state across non-linear handoffs; a failure in any worker required full pipeline restart with no checkpoint. LLM output is not serialisable as a worker message without losing structural context.

// PSEUDOCODE: H3 — local worker architecture (design-phase evaluation)
// Worker 1: brief generation
const briefWorker = new Worker('./workers/brief-worker.js');
briefWorker.postMessage({ campaignIdea, brandName, industry });

// Worker 2: image prompt derivation
briefWorker.on('message', (brief) => {
  const promptWorker = new Worker('./workers/prompt-worker.js');
  promptWorker.postMessage({ brief });  // full brief as serialised string
  // NEGATIVE RESULT: LLM partial output is not serialisable across worker boundary.
  // Worker failure requires full pipeline restart — no partial checkpoint available.
  // Non-linear handoffs (e.g., feedback cycle) require worker orchestration state
  // that workers cannot maintain statelessly.
});

// NEGATIVE RESULT: stateless workers cannot:
//   (a) checkpoint partial LLM output across a boundary failure
//   (b) propagate typed context (sections object) without serialisation loss
//   (c) implement non-linear handoffs (feedback cycles) statelessly

H4 — Iteration-First Orchestration: Cycle-as-Partition / Context-as-Asset

Each iteration cycle treated as a discrete partition. Context partitioned into typed assets (sections object) rather than raw strings. Re-execution replays only the failed partition — not the full pipeline. Bounded termination enforced at the orchestration layer via Promise.race, not delegated to the model or individual worker.

// services/campaign-brief-service.js : 29–83
// PSEUDOCODE: H4 — iteration-first: re-execute only the changed partition
if (existingGuide) {
  // Re-execution path: prior typed asset (existingGuide) is the context.
  // Only the changed partition is re-run — not the full pipeline.
  const userPrompt = `Here is the existing design brief:\n\n${existingGuide}
\nPlease apply the following feedback/changes:\n${campaignIdea}
\nReturn the updated brief with all sections, incorporating the requested changes.`;

  const response = await Promise.race([
    openai.chat.completions.create({
      model: 'gpt-4o-mini',
      messages: [
        { role: 'system', content: systemPrompt },
        { role: 'user',   content: userPrompt }
      ],
      temperature: 0.7,
      max_tokens: 1500
    }),
    // Bounded termination: enforced at orchestration layer, not by the model.
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('OpenAI API timeout (campaign brief update)')), 45000)
    )
  ]);
  // Context-as-asset: existingGuide is a typed, versioned asset threaded across cycles.
  // Cycle-as-partition: feedback re-execution is a discrete, independently-retryable unit.
}
// services/campaign-brief-service.js : 148–179
// PSEUDOCODE: H4 — context partitioned into independently-addressable typed assets
function parseBriefSections(content) {
  const sections = {
    campaignTitle:     '',  // independently addressable asset
    objective:         '',  // independently addressable asset
    keyMessage:        '',  // independently addressable asset
    visualDirection:   '',  // independently addressable asset
    designElements:    '',
    textLayoutGuidance:'',
    toneAndEmotion:    '',
    designerNotes:     ''
  };
  for (const [key, pattern] of Object.entries(patterns)) {
    const match = content.match(pattern);
    if (match && match[1]) sections[key] = match[1].trim();
  }
  return sections;
  // Each section is an independently-addressable typed asset.
  // Re-execution can target a single section without replaying the full cycle.
  // Context-as-asset: sections object threads across iteration cycles without
  // raw-string serialisation loss.
}

Scientific and Technological Advancement (STA)

Iteration-first orchestration model for multi-agent LLM workflows. Implementing design pattern: cycle-as-partition (each iteration cycle is a discrete, independently-retryable unit) and context-as-asset (context propagated as typed, versioned assets rather than raw strings). Corollary negative result: standard execution models each fail at a different part of the iteration boundary — single-call fails at re-execution, linear chains fail at context propagation, stateless workers fail at partial-state checkpointing. The negative results collectively define the boundary of the existing art. Principle transferable to any multi-agent LLM workflow requiring iterative refinement with partial failure tolerance.
