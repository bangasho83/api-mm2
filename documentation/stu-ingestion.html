STU-Ingestion

Architectural uncertainty in ingesting heterogeneous external marketing data sources with conflicting consistency, temporal, and rate-limit behaviours.

Ingestion Storage Orchestration Generation

Scientific and Technological Uncertainty (STU)

It was not known whether a generalised ingestion architecture could reliably retrieve data from multiple marketing API sources (Meta Graph API, GA4) that differ in consistency model, retrieval primitive, quota model, and mutation behaviour — without source-specific engineering for each.

H1 — Synchronous Retrieval (Single Request Per Source)

Single synchronous request issued per source with no chunking, no retry, and no token-refresh path. Collapsed under Meta Graph API rate limits for date ranges > 14 days, and silently terminated on GA4 OAuth token expiry mid-request.

H2 — Uniform Polling Cache (Same TTL Across All Sources)

In-memory TTL cache applied uniformly to all sources at the same interval. Meta Ads metrics are retroactively revised by Meta's attribution engine after the reporting window closes; a fixed TTL cannot distinguish between sources that mutate retroactively and those that do not.

// services/firebase-service.js : 595–609
// PSEUDOCODE: H2 — uniform TTL applied regardless of source mutation rate
const BRAND_CACHE = { data: {}, timestamps: {}, TTL: 1 * 60 * 1000 };   // 1 min
const ORG_CACHE   = { data: {}, timestamps: {}, TTL: 15 * 60 * 1000 };  // 15 min
// Both caches apply the same TTL policy to all sources.
// Meta insights mutate retroactively (attribution window revision);
// uniform TTL served stale spend/conversion figures without invalidation.

H3 — Generalised Windowed Pagination (14-Day Chunks)

14-day windowed chunking introduced for Meta retrieval. Resolved Meta volume failures but exposed that GA4 uses a different retrieval primitive (REST runReport body, not URL params) and a per-property daily token quota — a single windowing primitive cannot straddle both APIs.

// services/meta-ads-service.js : 83–129
// PSEUDOCODE: H3 — windowed pagination for Meta
if (daysDifference > 14) {
  let currentFrom = new Date(from);
  while (currentFrom < endDate) {
    let currentTo = new Date(currentFrom);
    currentTo.setDate(currentTo.getDate() + 13);       // 14-day window
    if (currentTo > endDate) currentTo = endDate;

    const chunk = await axios({
      url: `...act_${metaAccountId}/insights`,
      params: {
        time_range: JSON.stringify({ since: fmt(currentFrom), until: fmt(currentTo) }),
        time_increment: 1,
        cache_buster: cacheBuster  // bypass CDN/edge cache per chunk
      },
      timeout: 15000,
      headers: { 'Cache-Control': 'no-cache', 'Pragma': 'no-cache' }
    });
    insightsData = [...insightsData, ...chunk.data.data];
    currentFrom.setDate(currentFrom.getDate() + 14);   // advance window
  }
}
// GA4 uses runReport REST body (not URL params) + per-property daily quota —
// a single windowing primitive cannot be shared across both sources.

H4 — Consistency-Class Classification Framework

Each source classified along three orthogonal axes: consistency model (eventual vs. retroactive-mutation), retrieval primitive (Graph-insights vs. REST-runReport), and quota model (per-account-hourly vs. per-property-daily). Each combination determines retrieval strategy independently.

// services/ga4-service.js : 44–68
// GA4 classified: consistency=eventual, primitive=REST-runReport,
//                 quota=per-property-daily
// → strategy: refresh-on-401, no windowing required
const refreshAccessToken = async (refreshToken) => {
  const response = await axios.post('https://oauth2.googleapis.com/token', {
    client_id:     process.env.GOOGLE_OAUTH_CLIENT_ID,
    client_secret: process.env.GOOGLE_OAUTH_CLIENT_SECRET,
    refresh_token: refreshToken,
    grant_type:    'refresh_token'
  });
  return response.data.access_token;
  // Token refresh isolated to GA4 path; strategy derived from classification.
};
// services/meta-ads-service.js : 17–43
// Meta classified: consistency=retroactive-mutation, primitive=Graph-insights,
//                  quota=per-account-hourly
// → strategy: windowed chunking + cache-bust headers + long-lived token exchange
const refreshMetaAccessToken = async (shortLivedToken) => {
  const response = await axios.get(`${META_BASE_URL}/oauth/access_token`, {
    params: {
      grant_type:       'fb_exchange_token',
      client_id:        process.env.META_APP_ID,
      client_secret:    process.env.META_APP_SECRET,
      fb_exchange_token: shortLivedToken
    }
  });
  return response.data.access_token;
  // Token lifecycle and chunking strategy derived from classification axes,
  // not from ad-hoc per-API engineering.
};

✓ STA: Per-source retrieval strategy now derived from classification, not hand-crafted. Adding a new source requires classifying it on three axes — no new engineering per source.

Scientific and Technological Advancement (STA)

Consistency-class classification framework. Sources classified along three orthogonal axes (consistency model, retrieval primitive, quota model); each combination determines retrieval strategy independently. Demonstrated that a generalised windowing primitive (H3) fails when source quota models differ. Corollary: per-source strategy derivation from classification is transferable to any multi-consumer ingestion system adding new external data sources.
